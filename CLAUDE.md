# LUCAS Agent Team — Оркестратор

## Про проєкт

**Сайт:** https://www.lucasua.com  
**Репозиторій:** https://github.com/lucasukraine/lucas-astro  
**Технології:** Astro.js (статичний сайт), GitHub Pages (custom domain: www.lucasua.com)  
**Мова контенту:** Українська

**Що робить LUCAS:**
- Аудит та МСФЗ-звітність
- SAF-T Connector (власна платформа для ДПС)
- Міграція з 1С/BAS на Odoo
- Трансфертне ціноутворення
- Due diligence, оцінка активів, юридичні послуги

**Цільова аудиторія:** CFO, фінансові директори, головні бухгалтери, власники бізнесу (B2B, Україна)

## Команда агентів

| Агент | Роль | Тригер |
|-------|------|--------|
| `planner` | Технічний планувальник | Перед будь-якою розробкою |
| `coder` | Astro.js розробник | Реалізація планів |
| `tester` | QA та перевірка | Після змін коду |
| `reviewer` | Code review | Перед публікацією |
| `seo-specialist` | SEO стратегія та технічне SEO | SEO-задачі |

## Стандартні робочі процеси

### Нова функція сайту
```
planner → coder → tester → reviewer
```

### SEO-оптимізація сторінки
```
seo-specialist → coder → tester
```

### Нова стаття в блог
```
seo-specialist (ключові слова) → content-maker → fact-checker → reviewer
```

### Повний аудит сайту
```
seo-specialist + tester (паралельно) → planner → coder
```

## Правила оркестратора

1. Завжди починай з `planner` для технічних задач
2. `fact-checker` обов'язковий для будь-якого контенту про законодавство
3. Статті публікуються лише після approval від `fact-checker`
4. SEO-метадані перевіряє `seo-specialist` перед публікацією
5. Усі зміни коду проходять через `reviewer`
6. CTA (і верхня `<ArticleTocCta text="..." />`, і нижня `<ArticleCTA eyebrow=... title=... text=... />`) — текст має питати про ОСНОВНУ платну послугу LUCAS, під яку написана стаття (аудит / перехід з 1С-BAS на Odoo / SAF-T Connector (впровадження) / ТЦУ), або про вартість чи впровадження цієї послуги. Не використовувати формулювання про дії, які LUCAS не продає як окрему послугу з чіткою вартістю — ні як "побічну дію" (напр. "оцінити статус компанії", "діагностика готовності"), ні як вигляд самостійної "перевірки/аудиту" там, де насправді продається впровадження (напр. "перевірка SAF-T UA на відповідність контрольним співвідношенням ДПС", "перевірка файлу на помилки", "з'ясувати, чи підпадаєте під обов'язковий аудит" — усі ці формулювання описують діагностичну дію, а не послугу; правильно — "впровадження SAF-T Connector", "SAF-T Connector з вбудованою валідацією", "аудит для вашого підприємства"). Якщо немає точного релевантного формулювання — не передавати кастомний текст взагалі, лишати дефолтне значення компонента.
7. У H1 статей блогу (`<h1 class="art-h1">...</h1>`) усі крапки й двокрапки мають бути помаранчевими — обгортай кожну в `<span class="op">.</span>` або `<span class="op">:</span>` (CSS: `.art-h1 .op` у `src/styles/global.css`). Якщо в H1 є і двокрапка-розділювач, і трапляюча крапка — обидві обгортаються окремо. Крапка/двокрапка без `<span class="op">` в H1 — помилка, яку треба виправляти під час будь-якої правки заголовка. H1 обов'язково має завершуватись помаранчевим знаком: якщо заголовок сформульований як питання (починається з "Чи") — `<span class="op">?</span>`, у решті випадків — `<span class="op">.</span>`.
8. `overflow-x: hidden` для запобігання горизонтальному скролу сторінки має стояти ЛИШЕ на `html` (`src/styles/global.css`, рядок ~108), НІКОЛИ одночасно на `body`. Якщо задати його на обох — `body` стає власним scroll-контейнером (друга вісь автоматично рахується як `auto`), і будь-який нащадок з `position: sticky` (напр. `.service-context` — ліва sticky-колонка розділів послуг на головній) прив'язується до `body` замість viewport. `body` при цьому сам ніколи не скролиться (скролиться `html`), тому sticky-елементи перестають прилипати — це вже ламало sticky-колонку послуг на проді. Перед тим як додавати `overflow`/`overflow-x`/`overflow-y` на `body`, `html` чи будь-який спільний для всієї сторінки wrapper — перевір, чи немає десь на сайті `position: sticky`, залежного від viewport-скролу, і чи не з'явиться саме цей конфлікт.
